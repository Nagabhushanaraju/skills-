# 🤝 Contributing — Try Things Out!

> This isn't just a read-only resource. It's a sandbox. Break things, learn things, try things.
> Here's how to get involved.

---

## 👋 Who Is This For?

Anyone! You don't need to be a developer. You don't need to know how to code.

If you can type, you can contribute.

---

## 🧪 Things You Can Try

### 1. 🌿 Create a Branch and Practice

The whole point of this repo is to practice GitHub. So practice!

- Create a branch
- Make a change
- Commit it
- Open a pull request
- Merge it

The course walks you through all of this in the [README](./README.md).

---

### 2. 📝 Improve the Docs

See a typo? Something explained in a confusing way? A missing explanation?

Fix it!

Here's how:

1. Go to any `.md` file in this repo (like `GLOSSARY.md` or any file in `docs/`)
2. Click the **pencil icon** (✏️) in the top-right corner of the file
3. Make your change
4. Scroll down and write a short description of what you changed
5. Click **"Propose changes"**
6. Click **"Create pull request"**

That's it — you just made a real open-source contribution!

---

### 3. 💡 Suggest Something New

Have an idea for a new beginner guide? A section that's missing?

Open an **Issue**:

1. Go to the **Issues** tab at the top of this repo
2. Click **"New issue"**
3. Describe your idea
4. Click **"Submit new issue"**

An issue is just a public note — like a sticky note on the project board — saying "I think we should add this."

---

## 📋 Guidelines for Contributing

Keep it beginner-friendly:
- Use simple words. Avoid jargon unless you explain it.
- Use real-world analogies to explain technical things.
- Write as if the reader has never heard of Git before.

Keep commit messages clear:
- ✅ `Fix typo in GLOSSARY.md`
- ✅ `Add analogy for 'merge' concept`
- ❌ `update`
- ❌ `stuff`
